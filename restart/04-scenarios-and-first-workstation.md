# 场景筛选与第一个工序案例

日期：2026-10-17。用途：把探索方向转为可讨论的问题，并开始学习一个具体工序。尚未选定公司实际产线课题，以下建议不是项目立项或收益承诺。

## 1. 现阶段如何推进

业务侧可以继续收集产线希望改进的工序，实验室也可以主动带着问题走访。学习与产品准备使用一个匿名、可替换的参考工站，先建立分析与数据处理方法。

这两件事可以同时推进。真实场景确定后，用真实的设备、数据和指标校正参考案例。

## 2. 电子与机械制造中，值得观察的六类问题

下表是工程调研建议。优先级取决于现场发生频次、现有方案、可获得数据和改造条件，目前不打虚构的收益分数。

| 候选方向 | 到现场看什么 | AI 可能承担的部分 | 需要的主要数据 | 初步建议 |
| --- | --- | --- | --- | --- |
| 料盘取件、工位上下料 | 人是否反复取放、摆正工件，物料位置或型号是否经常变化 | 识别、定位、抓取与放置策略；固定动作可由原控制器执行 | 图像／深度、设备状态、有效命令、抓取和放置结果 | 优先寻找任务边界明确、可在独立工作台复现的工序 |
| 螺丝孔位对准与装配 | 找孔、对准、卡滞和返工发生在哪里，供料与拧紧已有何种设备 | 孔位定位、接近与对准、异常识别；拧紧使用明确工艺控制 | 图像、轴状态、命令、工具程序与扭矩／角度、装配结果 | 适合作为贯通数据、学习与传统工具的参考案例 |
| 换型与小批量切换 | 换工件后究竟改夹具、坐标、检测规则还是机器人程序，哪项最费工 | 辅助识别配置、适应位置变化、复用局部技能 | 规格／配方版本、标定、调整过程与换型后结果 | 优先定位一个具体变化，避免直接承诺自动适应所有产品 |
| 外观／漏装检查与复检 | 人在反复确认什么，是否已有 AOI，误报和漏报如何确认 | 检测、分类、异常提示；必要时由机器人调整观察视角 | 图像、缺陷定义、人工复核与最终质量结果 | 可作为 AI 合作切入口；固定相机任务可单独开展，无需机器人 |
| 连接器插接、压装与柔性件操作 | 力、接触、变形和遮挡是否主导失败，已有治具能解决多少 | 视觉与力融合、局部动作学习、失败检测 | 视觉、力／位移、命令、接触阶段和装配质量 | 作为后续扩展候选，先确认测量与工艺判定条件 |
| 物料周转、料箱取放与异常恢复 | 搬运距离、工位等待、人工介入原因，以及 AMR／输送线现状 | 调度、定位、抓取、重试或人工交接 | 任务事件、路线、物料／工位状态、操作轨迹与介入结果 | 分开判断移动与操作；是否需要双足取决于现场条件 |

公开参照：梅卡曼德提供小金属件取料的适用范围和部署说明；Micropsi＋DEPRAG 提供对准与拧紧分工的案例。它们支持把这些方向列为调研候选，不证明相同方案适合集团现场，也不提供我们的预期收益。[取料方案](https://docs.mech-mind.net/en/suite-best-practice/2.2.0/random-bin-picking/small-metal-parts-in-deep-bin.html)、[拧紧案例](https://www.micropsi-industries.com/mirai-cases/deprag-micropsi-automated-screwdriving)

## 3. 如何从候选里筛出一个真实课题

对每个工序，先填下列信息，缺失项写“待确认”：

- **问题**：哪个步骤出现了什么具体困难，谁需要改善它。
- **现状**：谁在做、已有设备能做什么，人工主要处理什么变化或异常。
- **基线**：每件耗时分布、失败／返工与介入情况；数量、时间范围和统计口径。
- **对照**：增加治具、调整照明、改供料或已有控制程序能否解决，代价如何。
- **数据**：能取得什么记录，是否能对齐到同一工件、步骤和结果。
- **边界**：先限定哪些物料、位置变化、工具与工况，哪些暂不覆盖。
- **试验**：能否先在独立工位验证，谁负责判定工艺结果。
- **验收**：比较任务完成率、质量、完整周期时间、人工介入和改造／维护成本。

优先考虑问题真实、边界清楚、结果可判断、能够获得样本且有人配合验证的任务。若简单工艺改造已经解决问题，可继续保留数据和追溯需求，不必强行安排模型训练。

## 4. 匿名现场调研卡

不需要向本项目提供厂名、产品名、客户、图纸或具体配方。可以在内网由团队保存原始信息，对外只描述抽象任务。

| 项目 | 示例写法／待填写项 |
| --- | --- |
| 匿名工序编号 | 工位 A／工序 01 |
| 任务 | 从料盘取壳体，放入夹具，完成连接 |
| 操作对象 | 硬质零件／小箱体／连接件等抽象类型 |
| 当前人工步骤 | 取件、摆正、对准、确认结果等 |
| 变化与异常 | 位置变化／型号切换／遮挡／卡滞等，发生频次待确认 |
| 已有设备与接口 | 机器人、相机、PLC、工具；具体开放接口待确认 |
| 可获得数据 | 视频、设备日志、工具结果、人工复核等 |
| 当前指标 | 实际测量后填写，不以印象代替统计 |
| 试点边界与验收人 | 待与现场确认 |

同一现象可能有不同原因，例如“对不准”可能来自定位、标定、夹具、控制或机械误差。调研先记录事实，后续再定位原因与决定技术路线。

## 5. 我们现在开始的参考案例

**名称：料盘取件 → 放入夹具 → 螺丝装配 → 结果记录。**

它是一个教学与需求分析用的假设工站，不代表公司真实工艺，也不是已确定的采购方案。首先使用固定工作台讲清操作，后续再讨论用 G1、自研机械臂或其他设备实现时的变化。

示例条件：一个便于夹持的刚性壳体、已知夹具、一种螺丝和明确的拧紧程序。供料器向工具供螺丝；“机器人从散料中捏起小螺丝”作为另一个更复杂的任务，不隐含在此案例里。

| 阶段 | 工作系统要做什么 | 数据侧要留下什么 |
| --- | --- | --- |
| 1. 准备 | 确认工件、夹具和工具就绪 | 工件／任务编号、配方、本体与标定版本、就绪事件 |
| 2. 取件 | 观察、确定抓取位置、抓起工件 | 观测、命令、实际状态、抓取结果 |
| 3. 放入夹具 | 移动、放置、确认并夹紧 | 轨迹与命令、到位和夹紧事件、放置结果 |
| 4. 对准孔位 | 找孔、接近、调整工具 | 图像、位姿／轴状态、有效示教或执行命令、控制方 |
| 5. 拧紧 | 按规定程序执行工具动作 | 工具命令、程序号、过程曲线与结束状态 |
| 6. 判定与交接 | 根据工艺要求判定，放行或进入处理 | 工艺结果、确认方式、失败原因与人工介入 |

图像定位、动作策略、轨迹规划、工具控制及质量判定分别评估采用什么方法，不要求全部使用同一个模型。

## 6. 第一小节：先分清两条流程

**工作系统的流程**发生在执行任务时：传感器观测 → 感知／策略／规划 → 控制器与工具 → 实际动作与结果。

**数据开发的流程**从记录开始：保存观测、命令和结果 → 检查与整理 → 构造样本 → 训练／评估 → 在满足适配条件后形成可用于工作系统的新模型。

两条流程通过采集和模型发布连接。数据管线负责组织这些记录及加工过程；机器人如何运动仍需要具体的控制与设备接口。

最容易混淆的三类记录：

| 记录 | 在本案例中的含义 | 可能的用途 |
| --- | --- | --- |
| 观测 | 此刻相机拍到的画面、轴位置、工具状态 | 作为模型输入或状态分析依据 |
| 命令 | 演示者／控制器此刻发出的目标动作、工具请求 | 满足有效性和语义条件时，作为动作学习标签 |
| 结果 | 是否放到位、是否按工艺完成拧紧、是否人工处理 | 评估、筛选和质量分析；不能直接替代连续动作标签 |

这一步的学习目标是能说清：“机器人工作时产生记录；数据管线把适用记录整理成样本；模型学到的能力通过控制链路回到设备执行。”
