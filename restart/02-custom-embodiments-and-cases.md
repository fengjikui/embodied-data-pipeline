# 范围补充：自研本体、传统自动化与专项机器人

整理与查证日期：2026-10-17。本文为需求补充和首轮案例笔记，不是最终选型报告，也不代表新版管线已实现。

## 1. 新增的核心方向

我们的目标是围绕产线任务建设可复用的数据与训练能力。G1 EDU 是首个实践对象，未来对象还可能包括自研专用机械臂、轮式设备、直线模组、夹具，以及现有机器人的改造工站。

用户提出的路线假设是：在相当一部分工业场景中，可以将感知、学习与自主决策能力加入已有自动化体系，不必把设备都做成人形。后续以实际工序验证其适用条件，暂不将它写成已被证实的市场主流判断。

讨论 SMT 等传统设备时，采用可衡量的说法：它能在规定工艺条件下高效自动运行；我们关注的新能力是如何处理物料变化、位置变化、异常和任务变更。“有无意识”不作为工程分类或验收指标。

对一个工序，需要一起比较：传统自动化、视觉引导与规划、学习式局部技能、通用策略，以及这些方法组合的方案。比较结果服务于节拍、质量、换型和维护目标。

## 2. 自研设备的数据管线，有哪些相同与不同

以下是本项目的设计建议，不是对所有厂商内部实现的描述。

共同流程仍是：采集与导入 → 时间和语义整理 → 质量检查 → 数据版本 → 面向目标训练任务生成样本 → 评估与运行结果回流。

差异主要出现在设备接入、数据含义以及最终训练样本的构造上：

| 环节 | 接入 G1 时要确认 | 自研机械臂／混合工站额外要确认 |
| --- | --- | --- |
| 本体描述 | 实际关节、手部、相机与控制模式 | 旋转轴和直线轴、轴间耦合、减速比、运动学、负载及工具变化 |
| 驱动接口 | 厂商 SDK 和实际开放能力 | 电机／驱动器接口、总线、PLC、夹具、供料与工具控制接口 |
| 观测 | 图像、关节、IMU、力等实际可用信号 | 编码器、压力、限位、工件在位、机床状态及质量测量 |
| 动作 | 哪些关节目标或末端目标可执行 | 连续运动目标与离散命令混合，例如移动、夹紧、供料、启动拧紧程序 |
| 时间 | 相机、状态、命令间的时间关系 | 传感器流、PLC 扫描、工具曲线、工艺事件的不同频率与时钟 |
| 标签 | 演示者给出的有效控制目标 | 示教、既有程序轨迹、人工纠正或工艺参数；逐项判断其能否成为目标标签 |
| 质量 | 是否抓住、搬到、放稳 | 工件号、工序号、扭矩／角度、尺寸／检测结果、返工与报废 |
| 部署 | 策略与机器人控制器的衔接 | 模型、运动控制器、PLC、工具之间的控制权及状态切换 |

例如，`action[0] = 0.2` 无法独立解释为动作。它可能代表关节位置 0.2 rad、直线轴位置 0.2 m，也可能是归一化值。必须一并记录通道名、含义、单位、坐标系、控制模式和适用设备版本。

ROS 的 `ros2_control` 官方接口分别描述关节、传感器和 GPIO，并提供命令与状态接口。这为异构设备建模提供了一个公开参考；它不表示任何电机接入后就自动具备完整机器人控制能力，也不决定我们必须采用 ROS。[官方接口文档](https://control.ros.org/jazzy/doc/ros2_control/hardware_interface/doc/hardware_interface_types_userdoc.html)

## 3. 管线应统一什么，保留什么差异

建议统一的是数据的身份、来源、时间含义、任务／工序关系、版本、校验和处理记录；同时保留本体与模型需要的具体字段。

首版可以预留以下边界，后续再由实际接入验证：

1. **设备接入**：把 SDK、日志或设备协议读出的内容转为可解释的原始记录。
2. **本体配置**：描述本体、传感器、工具、标定和控制接口；换工具或机械结构后产生新版本。
3. **任务与工艺**：描述执行阶段、工件、配方、成功条件、失败与人工介入。
4. **数据处理**：按数据类型执行时间处理、检查、筛选和追溯。
5. **模型样本导出**：按指定模型需要生成视觉样本、动作序列或其他训练输入。

连续流与事件应建立关联，不把所有信号强制压成相同帧率。原始高频曲线保留，训练时再按任务需要对齐和采样。不可用的通道应显式标记；填零不能自动等同于真实零测量。

尤其要区分三种数据：发出的控制命令、控制器接受或修改后的执行目标、传感器测得的实际状态。行为克隆的动作标签不能未经判断就用任意一组关节测量替代。

格式转换可能统一文件和字段，但无法凭空恢复缺失的深度、力、时钟关系或控制命令。不同本体即使用末端位姿表达，也仍需确认工作空间、工具、控制方式和任务是否兼容。

## 4. 用打螺丝说明混合工站的数据需求

设想一个自研设备：三个直线轴、一个旋转轴、固定拧紧工具和自动供料器。它的机械结构无需模仿人手，但仍然可能需要视觉定位和适应工件变化的能力。

一个设计候选流程是：

工件到位 → 识别工件和孔位 → 接近目标 → 调整对准 → 执行拧紧程序 → 读取质量结果 → 放行或进入异常处理。

其中哪些步骤用学习模型，要根据变化程度与已有控制能力决定。沿固定路线移动可以由现有控制器执行；有位置变化的对准可评估视觉规划或学习技能；拧紧参数与结束判定由经过验证的工艺方案确定。

需要关联保存的数据至少包括：

- 相机观测、轴状态、命令和标定版本。
- 当前工艺阶段、控制方、供料和夹紧状态。
- 工件号、孔位号、配方版本、工具程序号。
- 拧紧扭矩／角度曲线、设备结果码、后续质量检查与异常处理。

Atlas Copco 的公开资料将扭矩、角度、时间戳和序列号列为拧紧追溯数据。由此对本项目的直接启发是：装配管线需要能够关联工艺质量记录，只有视频和关节数据不足以说明装配质量。[拧紧工站说明](https://www.atlascopco.com/en-us/itba/local/products/tightening-cell-robotics)

这些记录可服务不同训练或分析目标：图像与孔位用于定位；观测与有效演示命令用于动作学习；过程曲线与经确认的质量标签用于质量分析；事件与失败原因用于诊断。不是每一项都需要送进同一个 VLA。

## 5. 首轮专项案例：证据和可借鉴之处

以下案例按与问题的相关性选择，不作为公司规模排名或采购推荐。资料查证到 2026-10-17；除明确列出的认证外，企业产品与生产信息均按发布方陈述记录，本项目未现场验收。

### 5.1 浙江深辰凯动：羽毛球连续对打

用户已确认这是其提到的羽毛球机器人，之前可能记混了地点。吉尼斯官网记录：浙江深辰凯动于 2025-12-22 在浙江绍兴完成与移动机器人 1,452 次连续羽毛球对打。该记录的发生地点为绍兴，不据此推定公司注册地。[吉尼斯记录](https://www.guinnessworldrecords.com/world-records/781002-most-consecutive-badminton-counter-hits-with-a-mobile-robot)

公司官网展示羽毛球机器人并宣称具备来球识别、预测和对打能力。本次查到的页面未披露可复现的网络结构、训练样本规范或损失函数，不能确认它采用 VLA、某种特定强化学习算法，或只有传统控制。[公司产品页面](https://www.zjsckd.com/)

这条记录证明特定条件下的连续对打成绩，不能直接外推到任意对手、全场竞技、工厂稳定运行或通用操作能力。

### 5.2 Micropsi＋DEPRAG：学习与传统拧紧工艺协作

Micropsi 公布的测试工站使用 UR16e：原生控制器接近工件，MIRAI 调整螺丝尖端对准孔位，DEPRAG 执行规定的拧紧扭矩或角度，再由原生控制器撤回。这是有明确控制权交接的混合方案，不应描述为一个模型包办全过程。[工站说明](https://www.micropsi-industries.com/mirai-cases/deprag-micropsi-automated-screwdriving)

DEPRAG 的合作公告也说明方案结合其拧紧技术与 MIRAI，以处理位置、角度和制造公差。两方材料确认合作与方案描述，未提供本项目可复现的内部模型配方或完整客户验收数据。[DEPRAG 公告，2023-05-09](https://www.deprag.com/en/article/automating-screwdriving-processes-with-ai.html)

Micropsi 另有 BSH 冰箱检漏案例，厂商页面报告进入 24/6 连续生产。它可以作为有生产应用描述的补充，不能把其运行成绩移用到前述螺丝测试工站。[BSH 案例](https://www.micropsi-industries.com/mirai-cases/bsh-automates-leak-testing)

### 5.3 梅卡曼德：视觉引导的工业抓取

官方深箱小金属件文档描述用 3D 视觉引导机器人抓取，并提供从需求到部署的流程。这条路线展示了工业视觉、抓取规划与机器人执行的组合价值；不能因其使用 AI 就自动归为端到端 VLA。[官方方案文档](https://docs.mech-mind.net/en/suite-best-practice/latest/random-bin-picking/small-metal-parts-in-deep-bin.html)

对本项目的启发是，部分数据的直接消费者可能是检测、位姿估计、标定或规划模块。公开部署说明并不等同于已获得开放训练数据、模型权重和全部现场指标。

### 5.4 Sony Ace：自定义非人形硬件与强化学习

这是技术机制较公开的研究对照，并非“小厂商”或工业量产案例。Sony 项目页说明采用高速视觉、仿真中的深度强化学习与专用硬件；硬件具有两个移动关节和六个旋转关节。训练在物理仿真中使用基于真人比赛记录初始化的情景。[Sony 项目页](https://ace.ai.sony/)

其 2026 年研究论文讨论与高水平选手的比赛评估。这里可借鉴的是围绕任务联合设计感知、硬件、训练和控制，而不是把比赛胜利理解为具备工厂通用能力。[研究论文](https://www.nature.com/articles/s41586-026-10338-5)

## 6. 如何初步理解“它为什么能打得这么好”

下面是帮助理解的功能拆解，不是对深辰凯动未公开实现的断言：

看见来球 → 估计位置与速度 → 预测可击球位置和时刻 → 选择回球目标 → 规划底盘与挥拍动作 → 执行并持续修正。

这些功能可能由不同方法组合完成。例如视觉模型估计球的位置，物理模型预测飞行，规划器计算相遇点，学习策略选择或调整动作，控制器驱动执行。模型是否输入自然语言、是否使用 VLA，需要另行查证。

作为公开对照，DeepMind 2024 年乒乓球研究明确描述了上层技能选择与下层控制的层级架构，以及仿真到真机迁移。它说明“专项能力很强”可以由多模块系统实现，不能仅凭效果推断是一个通用大模型。[研究摘要](https://deepmind.google/research/publications/107741/)

对数据管线的启发是：数据消费者还包括状态估计、预测、仿真参数校准和策略评估。后续深入时，要为每个消费者找出实际输入、目标与产物。

## 7. 首版如何兼顾未来

建议首版只选一个有可用数据和接口的配置，跑通导入、检查、可视化、版本记录和一个训练样本导出流程，再按条件接入采集与训练。当前尚未确定具体硬件配置，因此不宣称已确定真机遥操作方案。

同时用第二种差异明显的设备做扩展性检验：例如 G1 数据之外，再验证一个“少量轴＋工具事件＋质量结果”的仿真工站数据。它用于检查是否写死了关节数、手部类型和单一动作向量；模拟接入通过不等于真实驱动已接通。

后续再逐项实现真机适配、PLC 或工具协议、更多模型导出，以及跨平台安装与升级。每新增一种支持，都需要写明数据、软件和硬件的适用范围。
