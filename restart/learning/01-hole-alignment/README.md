# 第 1 小节：认识一条对准记录

本例完全由程序合成，不是真机遥操作数据，也未经过模型训练。图片是顶视示意图，不是真实相机照片。

**格式定位澄清（2026-10-17）：本例 JSON 的字段由本项目临时定义，仅用于说明观测和动作；既不是宇树官方采集协议，也不是 LeRobotDataset 格式，更不是新版管线已选定的中间格式。** 后续讲解改为对照官方采集结构、转换器和 LeRobot 实际样本，不把此示意当作 G1 的训练规范。

只研究固定高度、固定工具姿态下的平面移动。X 向右，Y 向上，位置与位移均在同一个固定工站坐标系中表达；所有数值仅用于教学。

## 文件

- `raw.jsonl`：3 条记录，每行一个 JSON 对象。
- `images/`：每条记录对应的示意图。绿色圆圈表示孔，蓝色十字表示工具尖端。
- `make_example.py`：生成代码，运行需要 Pillow；不会连接或控制机器人。

## 第一条记录的含义

- `timestamp_s = 0.0`：本段记录开始后的 0 秒，不是日期时间。
- `observation.image`：当前图片的相对路径，以本目录为基准。
- `observation.tool_xy_m = [0.098, 0.049]`：工具尖端当前的位置，即 X 为 98 mm、Y 为 49 mm。
- `action.delta_xy_m = [0.001, 0.0005]`：本例设置的有效示教命令，要求下一控制间隔相对当前参考位置向右移动 1 mm、向上移动 0.5 mm。它是位移命令，不是速度，也不是到孔的完整距离。

记录间隔为 0.1 秒。孔中心设置为 `[0.100, 0.050]` m。后两条记录给出理想化执行后的观测；真实设备的下一状态未必严格等于当前状态加位移命令。

孔中心是生成器设置的教学条件，没有作为一个额外字段直接塞进策略输入。后续构造样本时，再解释如何读取图片、选择状态与动作字段，以及生成张量。

本小节只要求分清：观测描述当前情况，动作字段记录示教者要求的移动。这里的 JSON 是自定义教学原始记录，尚不是某个现有训练框架要求的完整数据集格式。

## 后续采用的实际链路

宇树采集文件 → 与本体配置匹配的转换器 → 指定版本的 LeRobotDataset → 数据加载与策略预处理 → 训练批次。

宇树官方仓库提供 Unitree JSON 转 LeRobot 的脚本和训练示例。LeRobot 官方文档分别描述磁盘存储与加载后的张量；应分开查看二者。[宇树官方说明](https://github.com/unitreerobotics/unitree_lerobot#2-%EF%B8%8F-data-collection-and-conversion)、[LeRobotDataset 官方文档](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)

格式与框架版本、相机键名、状态与动作语义、策略适配需一起核实；转换成功不自动保证任意策略都能直接训练。
