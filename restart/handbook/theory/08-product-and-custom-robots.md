# T8：可视化产品、跨平台与自研设备

本章是后续产品的执行设计。当前交付的是文档和实验脚本，不将按钮原型或 CLI 标为生产产品。

## 普通使用者的一次任务

使用者选择设备配置与任务 → 检查连接 → 进入采集／导入 → 查看轨迹与异常 → 选择处理方案 → 生成有版本的数据 → 提交训练 → 查看模型与评估 → 在支持的环境验证运行。

“普通人可用”要求默认配置能解释、状态可见、失败知道如何恢复、输出能找到。真实控制操作还依赖具备条件的设备和现场流程，不能用一个按钮掩盖未完成的适配。

## 产品中的页面与后台职责

| 页面 | 用户操作 | 后台职责／验收 |
| --- | --- | --- |
| 设备与任务 | 选本体、相机、工具和任务 | 显示实际可用接口和配置版本；缺失项明确显示 |
| 采集 | 开始、停止、保存、标记接管 | 调用受支持采集适配器；记录状态与产物；未接设备不显示可采集 |
| 数据浏览 | 看相机、状态、命令、结果 | 按时序展示、标记异常和缺失；保留原始来源 |
| 处理与发布 | 预览处理方案、执行、查看结果 | 固定配置、进度、错误与重试、快照和划分 |
| 训练与评估 | 选兼容策略、资源、运行 | 预检字段与资源，记录环境、日志和检查点 |
| 支持与版本 | 更新、迁移、导出诊断 | 后端版本、数据兼容、恢复与回滚说明 |

## 最小实现顺序与验收

1. **离线数据工作台**：导入小数据、浏览、检查、生成版本。验收用户能找出缺字段与异常轨迹。
2. **训练任务接入**：将 L2–L3 步骤作为明确后台任务，先支持一种固定策略。验收用户能找到输入版本、日志、模型和预测。
3. **设备采集接入**：具备实际设备后，远程工作进程运行在 Host／PC2 等支持的平台。验收录制状态与文件一致，失败可恢复。
4. **异构工站扩展**：接入少轴设备、工具事件和质量结果。验收第二种本体不需修改与设备无关的质量／版本模块。
5. **生产运行**：补权限、备份、调度、监控、恢复、现场工艺与控制验收，分开记录软件和真实任务指标。

每一步保留单独验收和支持范围，首版不同时承诺所有模型、总线和机器人。

## 跨平台如何落实

浏览器 UI 可以运行在 Windows、Linux 或移动设备；设备工作进程可先限定官方验证的 Ubuntu。训练工作进程运行在其框架支持的服务器。三者通过明确 API／任务状态联系，UI 跨平台不表示所有驱动也跨平台。

配置使用相对路径、明确编码和可迁移地址，避免把开发电脑的绝对路径写入任务。安装说明区分 Python、CUDA、驱动和仿真依赖；发布时记录版本兼容范围。新版本先验证已有数据读取和失败恢复，再进行配置迁移。

## 自研机械臂与传统设备

新增本体要描述运动学、轴名称和类型、限位、状态与命令、工具坐标、控制接口、传感器与标定。旋转轴 rad 和直线轴 m 不能混成无说明向量。工具开始／结束、夹紧、供料等离散事件与连续动作分别定义。

设备驱动、通道配置、任务工艺、通用数据处理和模型导出分别适配。ROS2_control 的关节、传感器、GPIO 接口可以作为参考，最终是否采用要由实际协议与团队条件决定。[官方硬件描述](https://control.ros.org/jazzy/doc/ros2_control/hardware_interface/doc/hardware_interface_types_userdoc.html)

## 采购与现场准备清单

先确认 G1 EDU 具体版本和手部、所需开放接口、相机视角／深度能力、工艺力与精度、工具的程序与结果接口、工位条件、备件维护与软件支持。夹爪适合的任务和灵巧手的灵活性分别评估；腕部力传感器与拧紧工具内置扭矩测量也不是同一个信号。

自研设备要先验证关键轴与驱动的控制和测量能力，再确定学习方案。采购不能只按动作维度或厂商宣传视频选择。
