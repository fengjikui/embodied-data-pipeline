# T4：数据处理、质量、存储与版本

本章是本项目的工程设计建议；L2 仅实现其中的教学最小流程。

## 处理流水线的输入输出

| 步骤 | 输入 | 输出／必须保留的信息 |
| --- | --- | --- |
| 接入 | 原始目录、公开数据或设备日志 | 来源、许可、获取方式、文件校验 |
| 解析 | 格式版本与本体配置 | 可解释的观测、命令、事件和通道定义 |
| 检查 | 记录和任务条件 | 缺失、异常、接受／隔离原因 |
| 时间与坐标处理 | 时钟信息、标定、各数据流 | 明确的采样与变换结果、有效位和误差 |
| 划分 | 轨迹、场景、工件与采集批次 | 防泄漏的训练／验证／测试集合 |
| 发布 | 已接受数据、处理配置、统计 | 不可变数据版本及来源关系 |
| 模型导出 | 目标策略的特征约定 | 框架格式、统计与可加载样本 |

不能只把“转换脚本退出码为 0”当作数据合格。文件可读、语义适用、质量可靠和模型有效是不同的检查。

## 三种值需要分开

保留人的期望命令、控制器实际接受或裁剪后的目标、传感器反馈状态。它们可能不同。行为克隆应明确训练什么动作定义；只保存测量位置会丢失一些控制意图。

时间处理先确认采集时间、接收时间与设备时钟，再讨论重采样。选择过去最近样本会避免读取尚未出现的观测，但仍要限制陈旧时间；不是所有信号都适合插值。触发事件、接触变化、力峰值应保留原始记录。教学数据 `idx/fps` 是程序设定的名义时间，不能充当实机同步证据。

## 质量检查的两层

通用层检查文件完整、数值有限、维度和名字匹配、时间顺序、引用有效、重复轨迹等。任务层检查抓取是否稳、零件是否正确、装配质量是否通过、是否有人接管。末尾出现“成功”字符串不能替代工艺检验。

失败记录同样有价值，但用途需明确：可用于诊断、接管学习或奖励／质量模型，不能把失败动作不加区分地当作优质示范。

## 划分、统计和泄漏

同一条轨迹的相邻帧高度相关，随机按帧划分会让验证集过于相似。优先按原始轨迹／场景／采集批次分组，完整保留独立测试条件。归一化统计只从训练集估计，验证集使用训练时保存的变换。

L2 使用 4 条不同教学轨迹，前三条训练、最后一条验证；这说明划分机制，不代表有充分泛化评估。

## 存储和版本如何安排

生产候选目录：`incoming/` 接收区、`raw/` 原始文件、`quarantine/` 隔离项、`releases/` 发布数据、`runs/` 训练和评估。大文件可在对象存储，目录与关系放数据库；二者写入需要明确完成状态和恢复规则。

Git 管代码、配置、索引、文档；数据与权重另存，Git 里保存其地址、版本和校验。L2 的 SHA256 文件快照检查增加、删除和修改；它只是字节一致性，不是内容质量、合法授权或物理标定认证。

每个训练结果至少关联：数据快照、转换配置、训练／验证划分、统计、代码提交、完整环境、超参数、随机种子、检查点与评估记录。数据变更、新相机或新工具应形成新版本，不静默覆盖旧版。

## 工业化还需什么

大规模管线需要断点续作、幂等、事务、权限、审计、存储配额、备份恢复、监控和兼容迁移。L2 当前采用新目录、失败即退出、校验快照；未实现分布式调度与数据库事务。
