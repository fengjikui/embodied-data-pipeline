# T3：采集格式、LeRobot 存储与模型样本

读完应能分清：文件格式、通道语义、单时刻记录、时间窗口和训练批次。

## 第一层：采集程序原本保存的文件

宇树公开转换流程展示按任务和 episode 分目录，包含 `data.json`、`colors/`、`depths/` 等。目录存在不代表每种信号都已录入或被模型使用。

其转换器从 JSON 的 `states` 和 `actions` 中按所选机器人配置提取通道，再把图片键映射到相机键。通道顺序、手型和相机名称是协议的一部分。实际使用要锁定采集器、转换器与配置版本。[官方转换流程与代码](https://github.com/unitreerobotics/unitree_lerobot/blob/main/unitree_lerobot/utils/convert_unitree_json_to_lerobot.py)

`states` 通常表示采集时状态，`actions` 表示某种控制目标；它们是否为关节位置、速度或末端目标，必须读具体控制和转换定义。不能根据长度相同、都叫 `qpos` 就认为任意数据可互换。相机与力数据的单位、坐标、时钟也要分别记录。

## 第二层：LeRobotDataset 的磁盘组织

本手册实际读写 v3.0。表格数据使用 Parquet，图像可按配置存为视频等形式，元数据描述字段、形状、帧率、轨迹边界与统计。多个 episode 可以共用分片，因此不能按文件数量统计轨迹数。[官方格式设计](https://huggingface.co/docs/lerobot/lerobot-dataset-v3)

真实数据的 `meta/info.json` 是查看入口，具体文件名以该固定版本为准，不把某篇教程的目录强加给所有数据集。v2.1 与 v3.0 在组织方式上不同；迁移格式不改变本体与动作的物理含义。

## 一份真实 G1 数据的字段

L1 固定下载 `unitreerobotics/G1_Dex3_ToastedBread_Dataset` 的少量文件，版本见 `sources.lock.json`。它是公开的桌面操作数据，不是螺丝装配数据。

| 字段 | 本版本情况 | 含义与注意点 |
| --- | --- | --- |
| `observation.state` | 28 维 float32 | 双臂及 Dex3 手部相关状态；按 names 的实际顺序解释 |
| `action` | 28 维 float32 | 监督动作；单位和控制语义仍需与代码核对 |
| `observation.images.*` | 4 个视频相机键 | 左／右高位、左／右腕部图像；本实验不下载视频 |
| `timestamp` | 元数据帧率 30 Hz | 表中时间值；名义帧率不能独立证明跨设备已同步 |
| `episode_index` | 整数 | 这行属于哪段轨迹 |
| `frame_index`／`index` | 整数 | 轨迹内序号／全局序号，具体遵循 SDK |
| `task_index` | 整数 | 关联任务描述，不是动作标签 |

来源由 [固定数据版本](https://huggingface.co/datasets/unitreerobotics/G1_Dex3_ToastedBread_Dataset/tree/02cb29161f5adb2981a072aa35b408d82a556d07) 与下载校验记录确定。L1 的目录缺少视频和其他表分片，因此只能做有限查看，不能交给完整 SDK 假装它是完整训练集。

## 第三层：模型读取的样本与批次

以 L2–L3 的教学数据为例：SDK 把图像解码为张量，状态作为向量；按策略需要选择从当前时刻开始的 8 个动作。

| 数据 | 单样本形状 | 批次 B=2 的形状 |
| --- | --- | --- |
| 图像 | `[3,64,64]` | `[2,3,64,64]` |
| 状态 | `[28]` | `[2,28]` |
| 动作块 | `[8,28]` | `[2,8,28]` |
| 动作填充标记 | `[8]` | `[2,8]` |

3 是颜色通道，64 是教学图像尺寸，28 是本实验通道数量，8 是预测步数，2 是批量。它们不是所有 G1／VLA 的固定数字。

轨迹末尾不足 8 步时需要填充并标记，不能把补齐数据当作同等有效示范。训练时动作块作为监督目标；离线推理仅传入观测，再将预测与保留的参考动作比较。

归一化是另一道处理：按训练统计变换状态或动作的数值范围，推理输出再还原。它不等于把 rad 换成 m，也不会自动解决坐标不同的问题。ACT 是否消费任务文字需看模型实现；本实验 ACT 不把语言作为条件。

## 实操与复述

先运行 L1 的真实字段查看，再运行 L2 的官方导出和批次查看。分别说明你读到了原始文件、SDK 原生样本还是预处理后的模型输入。

关键问题：同样 28 维能否互换？视频路径如何对应某个 episode？为什么动作标签在推理时不能作为输入？
