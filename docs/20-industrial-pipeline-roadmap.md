# 工业级数据管线：架构、接入与验收差距

## 1. 当前原型和生产系统的边界

原型能完成小样本接入、原始快照/哈希、质检、组切分、不可变本地发布、训练视图、训练接口与固定 SDK 导出。本次增加异步数值对齐和接入资料检查。**它目前不是已上线的工业生产系统**：还没有多租户权限、生产对象存储、服务调度、数据库目录、断点任务、并发发布事务、真实 ROS2/MCAP 接入、多传感训练与工位 SLA 验收。

生产目标是“同一条数据能找到来源、语义、转换和使用的模型，坏数据不会悄悄进入训练，新批次能可靠重试，旧版本能恢复”。工业等级由真实环境的验收决定，不能用文件数量或单机演示替代。

## 2. 最小可落地的服务边界

```text
采集器 / 数据集镜像 / 仿真作业
      ↓ 完成批次 + 原始清单 + 本体/权限/时钟/工艺契约
Incoming 接收与完整性检查
      ↓
Raw 对象存储（原始文件只追加） + Catalog 元数据数据库
      ↓ 按批次排队；adapter / clock calibration / QC / session split
Canonical 分片（物理值、语义、事件、provenance）
      ↓ 按模型 recipe 生成，不改原始
LeRobot / RLDS / HDF5 / RL motion/rollout 训练视图
      ↓ 不可变 release manifest + 独立测试集
训练运行 → 模型登记 → 离线/仿真/工位评估 → 发布审批
      ↓
部署日志、工具结果与失败样本 → 新 Incoming 批次
```

这是规划架构；图中未实现模块明确见表。先用少量服务，按数据量与团队需求扩展，不建议第一天就部署全部中间件。

## 3. 存储与版本怎样管理

| 层 | 存什么 | 版本和写入规则 | 备份/权限 |
|---|---|---|---|
| incoming | 未完成审核的采集批次 | batch ID、上传状态，完成标记后消费 | 写入者与审核者分权 |
| raw | 原始视频、日志、配置、标定 | source/session/revision＋逐文件 SHA256，只追加 | 限制删除，保留策略与备份 |
| catalog | 文件与 episode 指针、契约、质检、任务状态 | PostgreSQL 等目录服务，事务 | 数据库备份与访问审计 |
| canonical | 对齐物理值、事件、媒体指针 | adapter/校时/QC commit、schema version | 可再生但保存追溯 |
| releases | 切分、统计、模型视图、manifest | 输入版本＋recipe＋代码哈希标识，发布后不可写 | manifest 完整性和恢复演练 |
| runs/models | 超参、模型/优化器、环境、评估 | run ID、数据 release、权重 hash | 模型 registry 与批准记录 |

小规模在内网 Linux 数据盘开始，大规模再用 S3 兼容对象存储＋数据库目录；Git 存代码、schema、recipe、索引和经脱敏的报告，不存工厂视频、模型大权重或秘密。DVC/类似工具可以管理指针与缓存，但它不是语义校验器，也不能替代目录事务。

目前本地 revision 存储和 release 哈希已实现。去复制的 CAS、多来源累计快照、数据库 catalog 与对象存储后端未实现；不能把现有累计 revision 复制包装成工业增量合并。

## 4. 作业生命周期与一致性

建议状态 `RECEIVED → LOCKED → VALIDATED → CANONICALIZED → VIEW_BUILT → REVIEWED → PUBLISHED`；失败进入 `FAILED/QUARANTINED`，保存原因，修复以新版本重新提交。

每一步输出到临时前缀，成功验证后写入完成标记；读者只读取已发布 manifest。任务幂等键可由输入 hash、adapter、schema、recipe 构成。并发相同任务用数据库唯一约束或租约；远端对象存储没有本地 rename 的全部语义，要用完成标记/事务指针，不能直接照搬单机目录写法。

重试必须有次数/超时与失败类别：网络中断可重试，数据维度/权限/语义错误应隔离而非无限重试。现有原型只有已完成 release 的复用，没有全阶段作业恢复/分布式并发保证。

## 5. 格式转换与时间处理

保留原始捕获时间与接收时间，记录每个设备时钟到统一钟的校正函数和误差报告。观测对齐用因果选择与最大年龄阈值；数值插值、掉帧补齐与图像重编码都产生派生版本，记录方法和损失。接触突变不能由通用线性插值“修复”。

canonical 不必是一个无限宽表：可把媒体、慢速标签、关节与高速力/触觉分别存表，用 session、clock、time 与索引关联。模型视图才按实际采样频率产生统一 batch。机器人实际关节、单位和坐标来自合同/控制器定义，不从 D_a 猜。

本次 `causal_align` 是纯数值同步组件，输入已经统一时钟；保留 index/age/valid。缺失或过旧输出 null 和 invalid，不补未来数据。它未实现设备校时、媒体/MCAP 解码或完整多模态 adapter。

## 6. 数据质量与切分

结构检查：哈希/解码/维度/数值/时间；语义检查：动作定义、关节顺序、单位、坐标、控制器；任务检查：阶段、接管、失败、工艺结果、异常原因；统计检查：覆盖矩阵、重复、偏置、场景泄漏。

在 segment 和窗口之前按 session 或更严格工件/工位划分。train-only 统计用于训练与部署，validation 用于调参，test 最终持出。成功示范进 BC 视图，失败/接管进恢复、结果预测或 RL 数据视图；一条轨迹可以有多种用途，但每个用途有不同标签规则。

## 7. Linux / Windows 与内网

基础接入、哈希、Parquet 与教学命令可跨平台；每个平台重建 `.venv`，锁依赖并各自验证。Linux 服务器是生产运行首选。机器人 DDS/ROS2、相机驱动、Isaac Lab/Sim、TensorRT 或第三方工具协议需要单独的 OS/驱动/设备兼容矩阵，不能因为基础 CI 是绿的就承诺全栈 Windows。

联网区预先收集固定版本的源码、平台 wheel、模型/数据许可证与哈希、驱动安装材料，形成带清单的转移包；在内网使用专用镜像/缓存。模型大权重按本次用户要求列候选，暂不在本机下载。平台依赖详见 [内网部署](10-linux-windows-offline-deployment.md)。

## 8. 分项交付与验收

| 项目 | 现状 | 生产验收方法 |
|---|---|---|
| 原始完整性、不可变本地 release | 已有实现与测试 | 注入损坏、重复任务、旧版本恢复 |
| 异步数值流因果对齐 | 本次实现，合成验证 | 真实钟差/延迟/掉帧与每流误差 |
| 接入资料与证据哈希检查 | 本次实现 | 缺配置/坏hash应阻止资料通过 |
| 多相机/力/工具训练视图 | 待实现 | 字段实际进入模型且影响任务评价 |
| ROS2/MCAP adapter | 待实现 | 真实日志转译、回放与语义检查 |
| 对象存储＋目录事务＋重试 | 待部署实现 | 断网/并发/崩溃故障注入 |
| 权限、脱敏与访问审计 | 待公司接入 | 越权拒绝、日志可追踪 |
| 保留/备份/恢复 | 待公司接入 | 用备份恢复指定 release 并复核hash |
| 生产监控与成本 | 待公司接入 | 延迟、失败率、容量/作业资源看板 |
| 工位成功与工艺质量 | 未验证 | 独立试验记录、工艺曲线、失败归因 |

规模/SLA 由实验室确定：每日 sessions/小时、每路码率、保留月数、并发训练数、接入延迟、恢复时间与可接受丢失量。容量估算为 `sum(各流每秒字节数)*录制秒数*批次数` 加版本、备份和派生开销；不凭机器人台数猜 TB。

## 9. 已做的检查不等于审批

`check_industrial_contract.py` 核验资料字段与附件 hash。即使文件齐全，也只能报告 `document_checks_passed`，始终输出 `human_review_required=true`、`robot_deployment_authorized=false`。它无法自动判断校准是否真实、授权是否覆盖生产、硬件是否安全或工艺能力是否合格。

这个边界让自动数据处理可持续扩展，同时避免把一个 schema 检查器当成工业认证。实机审批由现场设备/工艺/实验负责人按任务验收决定。
