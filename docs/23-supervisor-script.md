# 主管汇报：用7段讲清业务、系统、成果与下一步

建议8–12分钟，按听众问题展开技术细节。离线HTML默认展示主要结论；切换“技术详读”可展开本次完整报告。

## 1. 我们到底在做什么

“我们要建设从机器人采集到训练和任务评估的数据闭环。以G1 EDU为目标本体，以螺丝装配作例子，明确数据、模型和控制接口。当前交付是可运行原型与工业化设计，生产部署需要设备和工位验收。”

不要开场罗列模型名和下载规模。主管先需要知道：为什么做、用在什么地方、现在做到什么。

## 2. 数据从哪里来

“最直接的是目标机器人遥操作；真机和仿真都可遥操作。公开数据也是各种采集方式的集合。LeRobot是数据/工具生态，我们已能转换和读取；还要检查动作含义、本体配置和任务是否相关。我们暂不下载完整大数据，内网按固定版本和小样本验收后扩大。”

## 3. 用拧螺丝说明为什么不能只有一个模型

“完整任务包含到工位、取料、双手对位、接触、拧紧和复核。视觉和策略学习能帮助选料/运动；接触和平衡要由控制器处理，拧紧结果要来自工具/工艺检验。我们先固定站位，再扩展持工具移动。”

## 4. 模型如何学、怎么执行

“监督学习看示范动作，预测未来动作块。PPO通过仿真奖励更新运动策略。VLA可以加入语言与视觉基础模型，世界模型可以辅助预测和规划。部署时模型产生参考，匹配的控制器执行并持续反馈；不是接摄像头之后任其自己工作。”

如果追问loss：BC回归动作；ACT重建＋KL；token VLA交叉熵；flow/diffusion学习动作生成；PPO是概率比与优势。详细公式在模型报告。

## 5. 当前有哪几项可核查成果

“已有来源样本接入与不可变版本、原始追溯、训练窗口和固定SDK导出。此次补充异步数值流对齐、工业接入资料检查，并实跑BC训练/推理、官方ACT五次更新/离线推理和PPO教学。它们证明接口可运行，未证明G1会拧螺丝或在产线连续工作。”

演示选一条：数据窗口 → loss/checkpoint → 预测动作还原 → `robot_command_sent=false`；或时间对齐中缺样本为何不能拿未来值补。不要把教学回报与工厂指标混在一起。

## 6. 设备与路线怎么决策

“优先匹配实际G1手型与动作接口。可比较简单夹爪/固定拧紧模组与灵巧手手持工具；前者容易建立可测工艺基线，后者适合研究工具泛化。全身路线已列出宇树与NVIDIA公开入口，但需要配套控制器和目标数据。先做小样本接口验证，再根据固定测试集评价模型。”

## 7. 下一步需要主管协调什么

“请确定一个工位的工艺负责人和验收指标，取得G1具体配置/控制授权，明确工具/力传感采购与内网运行资源。我们先采10个完整episode试接入，然后对固定工位做基线与数据对照。工业运维同时按数据量建设对象存储、目录、权限、重试、监控和恢复。”

## 主管可能追问

| 问题 | 建议回答 |
|---|---|
| 什么时候可以上线？ | 先明确工艺/硬件/质量与节拍，用里程碑验收后给时间；目前不能按演示承诺产线日期 |
| 为什么不用开源数据直接训练？ | 需要对应任务/本体/控制语义；公开数据助起步，目标数据补工位与硬件差异 |
| 为什么不直接用最大VLA？ | 先有传统/ACT基线，按任务质量、延迟、算力和维护比较，不按参数数排名 |
| 需要灵巧手吗？ | 若有固定工具/供料，简单夹持可能足够；若研究手持工具和手内操作再比较灵巧手 |
| 行走和导航有什么区别？ | 一个稳定执行移动，一个决定路线/避障/停靠；全身协同处理操作时身体支持 |
| 世界模型可替代仿真/真机吗？ | 可辅助预测与规划；接触/工具质量必须真实验证，不以生成视频替代 |
| 已完成工业管线吗？ | 已完成可运行原型扩展与工业化方案，未完成公司服务/实机/工位SLA验收 |
| MIT能保证第三方数据都商业可用吗？ | MIT只覆盖项目自有代码/原创文档，模型与数据各自授权；智元NC等单独核查 |
| 怎么量化收益？ | 固定未见工件/session测试：完整成功率、工艺合格率、节拍分布、接管/返工、稳定性和成本 |
| 如何避免只做调研没有进展？ | 每阶段有命令、产物和验证报告；下一阶段有工位验收记录与模型/数据对照 |
