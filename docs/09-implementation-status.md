# 工程实现与验收状态

## 1. 已实现范围

| 模块 | 本次实现 | 边界 |
|---|---|---|
| 来源锁 | 固定 revision、URL、本体与权利说明、逐文件 SHA256 和字节数 | 许可为来源记录，不是法律授权意见 |
| 原始层 | 按 source / revision 保存，拒绝哈希不同的覆盖 | 未实现远端对象存储服务 |
| Reader | 指定 LeRobot v2/v3 子集，本地 lab_json_v1 | v3 元数据 reader 当前固定一个 metadata shard；不保证读取任意来源 |
| 规范层 | 完整数值轨迹、时间、当前语言与来源 sidecar | 原始文件保留未投影模态；未构建统一 ROS topic 契约 |
| 质量 | 维度、有限值、单调时间、连续索引、语言、视频、源时间对齐 | 未验证实际物理标定、力学极值或人工任务质量 |
| 去重与分割 | 同本体数值完全重复检测；origin_group 稳定 hash split | 不做近重复视频识别；无法自动发现未标注的跨集同源关系 |
| 统计与窗口 | 每来源训练集统计；8 步动作块；尾部 mask；不跨 episode | 不做跨本体归一化或动作空间转换 |
| 发布 | recipe + lock + code hash 标识，临时写入后发布，文件完整性复验 | 单写入进程，本地文件系统；无分布式事务 |
| 训练 | CPU 小型多模态 BC，有限 loss/梯度与检查点恢复 | 随机初始化，无上游预训练 VLA 骨干 |
| 平台 | Python 3.12、uv.lock、核心入口不依赖特定桌面系统命令 | Ubuntu / Windows CI 验证状态见最终验收；真实内网仍需复验 |

`docs/03-pipeline-design.md` 是完整设计目标，本文件是实际实现清单。它们不是同一个完成度口径。

## 2. 为什么当前视图叫 interface_smoke

原始数据里的动作、关节标签和控制器含义尚未全部核验。源数据未给出已审计的逐轨迹成功标注，因此不能将每条记录自动视为专家成功示范。图像对齐采用源时间假设，没有实测硬件采样和传输延迟。

这些数据可以检验文件、张量、loss 与梯度接口，但尚不具备严格的工业行为克隆发布条件。程序只接受 `interface_smoke` 视图，其他视图显式拒绝；报告不声称已产生可直接部署的 openpi / GR00T 训练集。

## 3. 实测证据

- `reports/acceptance.json`：18 条来源轨迹、23,109 个时刻、590 个窗口；离线复用、训练统计、防跨轨迹、mask 与归一化往返误差。
- `reports/training_probe.json`：三组 CPU 探针的模型参数、输入形状、训练／验证误差、耗时和恢复结果。
- `reports/episode_quality.json`：每条轨迹的时间对齐、维度、语言、来源、split 和质量告警。
- `reports/pipeline_manifest.json`：发布 ID、完整输出哈希和处理配方。
- `tests/`：无网络的规则与端到端集成测试，包括新增数据后切分稳定、旧版本仍可验证、自采登记、重复和异常。

训练／验证划分是从公开来源原有 train 范围内形成的小型工程留出，不能作为官方 benchmark 成绩。相关任务可能在基础模型预训练中出现过；当前未使用基础模型，不据此作任何泛化结论。

## 4. 下一阶段技术优先级

1. 选定一个目标本体与模型，核实状态、动作、手型、坐标、单位和控制时序，完善成功／失败标注。
2. 在公司服务器运行当前真实小样包，记录平台、存储和编解码结果，再接上所选模型官方加载器。
3. 增加官方模型 adapter 与模型级集成测试；先验证一个 batch，再开展可解释的小规模微调。
4. 连接可用仿真／机器人，固定初始条件和任务成功标准，建立完整试验日志。
5. 增加场景、操作者、对象和采集会话分组，做数据量与数据来源的对照实验。
6. 根据实际数据增长再建设对象存储、调度、监控、人工复核和近重复检测。

不以代码行数、下载 TB 数或训练 loss 下降作为工业能力验收标准。
