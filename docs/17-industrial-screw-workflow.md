# 从数据到 G1 双手螺丝装配：完整业务流程

核查日期：2026-10-14。本文是实验室方案，G1 EDU 配置和工艺尚未确认。最新汇报入口：[离线报告](../deliverables/industrial-report.html)，配套 [模型](18-models-objectives-inference.md)、[全身协同](19-whole-body-coordination.md)、[工程架构](20-industrial-pipeline-roadmap.md)、[采购与来源](21-ecosystem-data-hardware.md)、[命令实操](22-command-learning-lab.md)。

## 1. 先修正三个概念

你的理解可以整理为：**采集或获取轨迹 → 保留原始和语义 → 质检与同步 → 按任务切分 → 按模型导出 → 训练 → 评估 → 控制器闭环执行 → 回流失败数据。**

“遥操作”描述谁发出动作：人通过 VR、主从机械臂、手柄或拖动示教控制机器人；被控制对象可以是真机，也可以是仿真机器人。“仿真”描述环境：相机、接触和关节读数由模拟器产生；动作可以来自人、脚本或训练中的策略。“开放数据”描述获取渠道与权利，也可能正是遥操作数据。LeRobot 描述存储与工具生态。它们是独立维度，不能作互斥分类。

LeRobot 文件能被 DataLoader 读取，只意味着字段、媒体、episode 和索引可解析。它没有自动证明：相机适合小螺丝、手型匹配、动作单位正确、数据包含拧紧过程、训练脚本使用了这些字段，或输出能接到 G1 控制器。

## 2. 以“拧螺丝”把目标变得可测

主管的业务需求应该写为：“把指定规格螺丝装入指定工件的孔，并通过规定的扭矩/角度或其他工艺检验，在允许时间内完成，失败可检测、可恢复。”不是只写“学会拿螺丝”。

首先确认：螺丝规格与头型、螺孔材料/公差/螺纹、是否有预定位与自动供料、工具质量与反扭矩、工件治具、允许的返工、节拍以及质量判定。**本文不填写尚未确定的扭矩、力或速度限值**，这些要由工艺与设备负责人定义。

| 阶段 | 系统行为 | 需要的观测/标签 | 第一版建议 | 单独验收什么 |
|---|---|---|---|---|
| 到工位 | 行走、避障、停靠 | 地图/位姿、障碍、目标、速度命令、接管 | 先用已有运动控制器与导航 | 到达率、停靠误差、碰撞和接管 |
| 识别取料 | 找螺丝、区分规格、抓取 | 头部/腕部图像、关节、夹爪/手动作、工件 ID | 固定供料位置，比较视觉伺服与 BC/VLA | 取错、漏取、掉落 |
| 双手对位 | 一手扶持/定位，一手带工具接近 | 两臂状态/命令、TCP 位姿、两手角色、接触 | 先固定站位，联合预测两臂动作或分技能 | 对位误差、相互碰撞、工件移动 |
| 入孔与接触 | 轴线对齐、插入、保持轴向力 | 力/力矩、触觉、相机、工具状态、失败标记 | 视觉引导＋经验证的阻抗/导纳/接触策略 | 卡滞、滑牙、偏斜、异常力 |
| 拧紧 | 驱动工具、受力稳定 | 工具转速、扭矩/角度曲线、程序 ID、OK/NOK | 采用可记录结果的拧紧控制器 | 工艺合格、过扭、欠扭、滑牙 |
| 复核与退出 | 检查、释放、重试或交给人 | 工具结果、视觉、故障码、恢复分支 | 明确状态机与次数上限 | 真实质量、误判、返工与耗时 |

这是本项目建议的混合架构，不是任何厂商生产系统的内部结构声明。**取料可以成功但拧紧仍失败**；BC 训练误差下降不意味着螺纹质量合格。

## 3. 三种工具方案怎样影响数据与模型

| 工具方案 | 适合先做什么 | 数据变化 | 主要工程约束 |
|---|---|---|---|
| 灵巧手持普通电钻/电批 | 人类工具迁移研究、握持和按扳机 | 手指、触觉、工具相对位姿、扳机动作 | 握持防滑、反扭矩、工具结果能否读取 |
| 手持可联网工业拧紧工具 | 同时研究手持工具和工艺闭环 | 增加 cycle ID、目标程序、扭矩/角度结果 | 厂商协议、质量追溯、重量和载荷 |
| 腕部固定拧紧模组＋供料/治具 | 优先验证可测的装配闭环 | 固定 TCP、工具启停/程序、曲线与结果 | 机械安装、供电、反扭矩和全身平衡 |

工程上建议先比较“固定模组/治具”与“手持工具”两条基线，选能稳定读取工艺结果的路线。不因人形外观就要求每一步复刻人手操作。两个手的角色也可以改变：一手扶工件、另一手拧紧；或者供料器预放螺丝，让一手直接操作工具。

## 4. 一条真实轨迹需要保存什么

采集 session 是一次有明确硬件、时钟、操作者和工位配置的连续录制；episode 是一个完整尝试；segment 是 episode 内的取料、对位、接触等阶段。**同一 session 切出来的 segment 必须在同一 train/validation/test 组**。

原始数据包括图像/视频及曝光时间、实际关节位置和速度、原始操作输入、发出的目标动作、控制器实际接收/执行信息、力/触觉、IMU/基座状态、工具记录、接管事件、标定和质量结果。命令目标 `q_target` 与测得位置 `q_measured` 都保留；不能把未来测得位置偷偷替代动作标签。

语义示意，不是 G1 的字段顺序或可执行命令：

```json
{
  "session_id": "factoryA_stationB_captureC",
  "episode_id": "attempt_0001",
  "capture_time_s": 12.050,
  "clock_id": "lab_clock_after_calibration",
  "instruction": "将指定螺丝装入工件孔并按工艺拧紧",
  "phase": "align",
  "observation": {
    "images": {"head": "frame_reference", "left_wrist": "frame_reference"},
    "q_measured": "vector with explicit joint_names and rad units",
    "wrench": "Fx,Fy,Fz,Tx,Ty,Tz with frame and N/Nm units"
  },
  "command": {
    "representation": "declared joint targets OR TCP targets, not inferred",
    "controller_id": "versioned controller and mode",
    "tool_program_id": "process_owner_defined"
  },
  "event": {"intervention": false, "fault": null},
  "outcome": {"tightening_result": null, "success": null}
}
```

末尾结果可以是评估或奖励标注，但**不能在推理前作为模型输入**。阶段语言只在其生效时刻以后可见；不能把整个未来流程拼给每一帧。

## 5. 从采集到模型的具体转换

1. 完成录制与文件关闭，接收到独立 incoming 批次，检查来源、许可、文件大小与哈希。
2. 原始数据只追加，记录机器人配置/控制器/相机/手型/标定 revision。新手型不是同一动作契约。
3. 用 adapter 解析 XR JSON、LeRobot、ROS2/MCAP 或模拟器日志。当前仓库已支持前两类和实验室 JSON，尚无 ROS2/MCAP adapter。
4. 把硬件时钟转换到经验证的统一时间基准，记录 offset/drift/时延。观测使用不晚于当前锚点的最近样本，过旧则无效；不默默插值接触事件。
5. 建立完整 episode 及动作契约，隔离缺失媒体、错单位、重复/越界时间、未确认控制语义。失败轨迹保留，但不能全部当成功示范训练。
6. 先按 session/工件/工位划分，再切窗口和计算 train-only 统计。持出一批不参与调参的 test；当前原型只实现 train/validation。
7. canonical 保留物理值和所有关键字段，再生成指定模型的训练视图：相机顺序、分辨率、语言处理、动作块长度 H、归一化、padding/mask。
8. 保存 release、recipe、adapter commit、数据权限与训练运行环境，训练脚本读取固定 release；checkpoint 和统计一同归档。
9. 先离线回放，再仿真闭环与固定工位实验，达到任务卡要求后再做持物行走/产线试验。推理的新日志重新进入 incoming。

异步数值流教学实现见 `src/vla_pipeline/synchronize.py`。它要求输入已经校时，不能替代真实时钟标定；它没有自动接进旧 XR importer，也没有实现多相机/力数据的训练后端。

## 6. 数据怎样具体提升能力

| 数据变化 | 学到的关联 | 改善的预期 | 怎样证明 |
|---|---|---|---|
| 增加光照/遮挡/螺丝摆放 | 图像变化下对应正确抓取动作 | 视觉与抓取鲁棒性 | 固定未见工件与光照下比较 |
| 成对记录语言/规格/动作 | 指令区别应改变取料与程序 | 任务选择 | 改指令并比较正确取料，不能只看语言 embedding |
| 增加接触与受力记录 | 接触状态对应顺应/退出动作 | 入孔与恢复 | 真实卡滞/偏斜试验和工艺检测 |
| 同步双手动作 | 两手角色和相对动作相关性 | 双手协作 | 工件稳定、对位误差、碰撞 |
| 负载变化与全身状态 | 手臂/工具改变身体受力 | 持物移动稳定性 | 在确认负载范围内的闭环验证 |
| 失败＋接管＋修正示范 | 识别偏离并转向恢复 | 恢复与减少人工干预 | 接管率、恢复率和误判 |

“预期改善”是待验证假设。开展 target-only、public+target、sim+target 三组对照，保持测试集、模型、训练预算和评估流程一致；避免把更多计算误认成更好数据。

## 7. 第一批实际该采多少

优先先采 **10 个完整试采 episode** 用来验字段、时钟、图像与工具日志，不用于宣称能力。随后可按工艺条件建立 50–100 次成功/失败尝试的试验矩阵；这是起步实验建议，不是保证模型学会的阈值。覆盖不同操作者、不同日期、典型摆放和可控失败，统计每个格子的独立 session 数。按学习曲线扩充，而不是先下载 TB。

先固定站位与低复杂度治具，评估 ACT/传统伺服基线，再比较小 VLA 和 G1 专门路线；行走采用独立仿真/控制器路线。选择依据见下一篇。

参考工具接口与控制器能力：[宇树采集工具](https://github.com/unitreerobotics/xr_teleoperate)、[宇树 IL](https://github.com/unitreerobotics/unitree_lerobot)、[Atlas Copco 拧紧系统](https://www.atlascopco.com/content/dam/atlas-copco/industrial-technique/general/documents/brochures-leaflets/electric-assembly-tools-and-systems/Smart%20Tightening%20Strategies%20Leaflet.pdf)。工具厂商声明不是本实验室已完成的装配验证。
