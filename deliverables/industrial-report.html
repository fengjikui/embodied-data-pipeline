核查日期：2026-10-14。本文是实验室方案，G1 EDU 配置和工艺尚未确认。最新汇报入口：离线报告，配套 模型、全身协同、工程架构、采购与来源、命令实操。

1. 先修正三个概念

你的理解可以整理为：采集或获取轨迹 → 保留原始和语义 → 质检与同步 → 按任务切分 → 按模型导出 → 训练 → 评估 → 控制器闭环执行 → 回流失败数据。

“遥操作”描述谁发出动作：人通过 VR、主从机械臂、手柄或拖动示教控制机器人；被控制对象可以是真机，也可以是仿真机器人。“仿真”描述环境：相机、接触和关节读数由模拟器产生；动作可以来自人、脚本或训练中的策略。“开放数据”描述获取渠道与权利，也可能正是遥操作数据。LeRobot 描述存储与工具生态。它们是独立维度，不能作互斥分类。

LeRobot 文件能被 DataLoader 读取，只意味着字段、媒体、episode 和索引可解析。它没有自动证明：相机适合小螺丝、手型匹配、动作单位正确、数据包含拧紧过程、训练脚本使用了这些字段，或输出能接到 G1 控制器。

2. 以“拧螺丝”把目标变得可测

4. 一条真实轨迹需要保存什么

采集 session 是一次有明确硬件、时钟、操作者和工位配置的连续录制；episode 是一个完整尝试；segment 是 episode 内的取料、对位、接触等阶段。同一 session 切出来的 segment 必须在同一 train/validation/test 组。

原始数据包括图像/视频及曝光时间、实际关节位置和速度、原始操作输入、发出的目标动作、控制器实际接收/执行信息、力/触觉、IMU/基座状态、工具记录、接管事件、标定和质量结果。命令目标 q_target 与测得位置 q_measured 都保留；不能把未来测得位置偷偷替代动作标签。

5. 从采集到模型的具体转换

  1. 完成录制与文件关闭，接收到独立 incoming 批次，检查来源、许可、文件大小与哈希。
  2. 原始数据只追加，记录机器人配置/控制器/相机/手型/标定 revision。新手型不是同一动作契约。
  3. 用 adapter 解析 XR JSON、LeRobot、ROS2/MCAP 或模拟器日志。当前仓库已支持前两类和实验室 JSON，尚无 ROS2/MCAP adapter。
  4. 把硬件时钟转换到经验证的统一时间基准，记录 offset/drift/时延。观测使用不晚于当前锚点的最近样本，过旧则无效；不默默插值接触事件。
  5. 建立完整 episode 及动作契约，隔离缺失媒体、错单位、重复/越界时间、未确认控制语义。失败轨迹保留，但不能全部当成功示范训练。
  6. 先按 session/工件/工位划分，再切窗口和计算 train-only 统计。持出一批不参与调参的 test；当前原型只实现 train/validation。
  7. canonical 保留物理值和所有关键字段，再生成指定模型的训练视图：相机顺序、分辨率、语言处理、动作块长度 H、归一化、padding/mask。
  8. 保存 release、recipe、adapter commit、数据权限与训练运行环境，训练脚本读取固定 release；checkpoint 和统计一同归档。
  9. 先离线回放，再仿真闭环与固定工位实验，达到任务卡要求后再做持物行走/产线试验。推理的新日志重新进入 incoming。

异步数值流教学实现见 src/vla_pipeline/synchronize.py。它要求输入已经校时，不能替代真实时钟标定；它没有自动接进旧 XR importer，也没有实现多相机/力数据的训练后端。

展开：原理、字段、方案与复现细节

核查日期：2026-10-14。以下区分通用算法原理、上游实现与实验室选型。生产模型训练尚未在本仓库执行；现有真实训练是小型 BC 接口探针，本次新增 PPO 教学。

1. 先区分模型承担的工作

VLA 是用视觉 V、语言 L 和本体状态生成动作 A 的策略家族，不是固定一个 Transformer 结构。一个工程系统还可能包含视觉检测/几何、导航、任务状态机、力控、全身控制以及工具控制器。ACT、Diffusion Policy 可以是没有语言输入的模仿学习策略，不应自动称为 VLA。

共同形式是：o_t = 图像历史 + 状态 + 可获得的指令，策略输出 A_t = [a_t, ..., a_(t+H-1)]。同样是 action，可能表示关节目标、末端位姿增量、速度、力矩或某个全身控制器的运动 latent。输出维度相同也不代表动作含义相同。

3. 监督学习的标签到底是什么

LLM SFT 的 label 是目标 token；机器人 BC 的 label 通常是人示范时发出的动作目标。当前状态是输入，接下来的动作块是监督标签。视频中的对象位置不是默认动作标签；任务成功 success=true 也不是动作向量。

例如观测 batch：images [B,K,3,h,w]，state [B,D_s]，language token IDs [B,L]；标签：actions [B,H,D_a]；有效性：mask [B,H,D_a] 或框架规定的逐时刻 pad mask。K 是相机数，H 是预测步数。我们的已有 NPZ 接口只有一路相机；下文多相机是模型契约示例。

训练期动作未来 H 步作为标签合法，未来图像/终局结果作为当前输入则泄漏。跨 episode 的末尾用 padding 与 mask，不从下一次尝试取标签。原生动作先保留，再按 train-only 统计处理；部署使用训练时相同统计，不能随现场新样本改均值。

4. 损失函数对照

4.1 连续 BC

L_MSE = sum(mask * (pred_action - demo_action)^2) / sum(mask)。

这是仓库 training.masked_mse 的真实目标。动作归一化改变各维损失权重；物理误差仍需逆归一化后按单位报告。虚构两维合成数据上的 loss 不能用来衡量 G1 扭矩或定位精度。

4.2 ACT

L_ACT = L_reconstruction(pred_chunk, demo_chunk, pad_mask) + beta * KL(q(z|state,demo_chunk) || N(0,I))。

训练时 encoder 用示范动作估计 latent，decoder 用观测和 latent 预测块；推理不能把真实未来动作送 encoder，通常使用先验 latent 的指定值。锁定 SDK 的 ACT 使用 L1 重建和 KL，而不是本仓库探针的 MSE。具体 padding 归约规则以代码为准。ACT 官方说明、原论文与实现。

4.3 Diffusion Policy

示例 DDPM 目标：a_k = sqrt(alpha_bar_k)*a_demo + sqrt(1-alpha_bar_k)*epsilon，L = E[||epsilon_theta(a_k,k,o)-epsilon||²]。噪声是训练目标，背后仍由示范动作生成训练样本。推理从随机噪声反复去噪，得到动作块。该路线能表示多种合理动作，采样次数影响延迟。作者项目。

4.4 自回归动作 token

将物理动作按指定 tokenizer 离散化，L_CE = -sum log p(action_token_i | o, instruction, previous_tokens)。OpenVLA 原版是这一路线；tokenizer、bin 范围与归一化要一同部署。训练 token 准确不等于闭环成功；某些后续变体的动作头不同，不混写成原版行为。OpenVLA。

4.5 Flow matching

取噪声 z~N(0,I) 和示范 a，一种约定为 x_tau=(1-tau)z+tau*a；目标速度 v*=a-z，L=E[||v_theta(x_tau,tau,o,l)-v*||²]。推理从 tau=0 的噪声积分到 tau=1 的动作。不同实现可反向定义 tau，因此不能直接拷贝符号而忘记路径约定。SmolVLA、openpi。

6. PPO 用什么数据、什么模型、什么目标

机器人行走常用仿真中的 on-policy PPO。actor 输入 deploy-time 可得的关节、IMU、运动命令与历史，输出关节目标偏移或控制动作；critic 训练时可以额外用地形/真实速度/物理参数等 privileged state。是否采用非对称 actor-critic 要查具体任务实现；不能把训练才有的信息误接进部署 actor。

环境每步输出 o_t,a_t,r_t,o_(t+1),terminated,truncated。还记录旧策略 log probability 与价值。标签不是“正确脚步”，而是奖励定义下的优势/回报。奖励可能包括速度跟踪、平衡、能耗、姿态、接触、碰撞；奖励设错也会训练出投机策略。

PPO 核心：ratio=exp(new_log_prob-old_log_prob)；最大化 mean(min(ratio*A, clip(ratio,1-eps,1+eps)*A))。最小化时取负号。critic 拟合回报，常加价值损失和 entropy 项；GAE 用 TD 残差构造优势。真正终止通常不 bootstrap；时间上限截断若对应 continuing task 应用终止前观测 bootstrap，不能用 reset 后观测。代码实现要区分这两种 done。

推理时通常只需 actor 和观测归一化/历史栈，不需要计算 PPO loss、GAE 或运行 critic。仿真训练还需机器人模型、关节限制、PD 增益、延迟和动力学；sim2sim 验证，再依据实机合同做 sim2real。见 宇树 RL、rsl_rl、PPO 原论文。

本次 PPO 代码是一个虚构的一维有限时域环境，actor/critic 都是小 MLP，观测含剩余时间，最后一步是真正终止。它让你逐项检查 rollout、优势、ratio、checkpoint 与 actor 推理；没有机器人接触物理或步态，不证明行走能力。

7. RLHF 知识怎样迁移过来

PPO 的概率比、优势与 clipping 和你熟悉的 LLM PPO 共通，但机器人“环境反馈”是接触、运动与工具结果，不是文本偏好；actor 常输出连续分布，不是 token。GRPO/DPO 并不是走路的默认训练方法。接触技能也可能使用离策略 actor-critic，例如 SAC，或人接管辅助 RL；这通常需要在线 replay buffer、奖励/重置机制与控制接口。SERL。先做好可重复的 BC 基线，再决定是否需要 RL。

8. 训练设备与选型顺序

数据接收、哈希、Parquet 质检通常是 CPU＋存储 I/O；模型训练依模型/分辨率/H/batch 选择加速器；大量物理仿真有其独立 GPU/驱动需求；实机推理需满足端到端周期和时延，训练服务器不必放在机器人上。

实验室可规划使用昇腾 A3 资源，但具体型号/内存/CANN、PyTorch/torch_npu、占用与访问尚未核实。不能因为“有 A3”就声称 Isaac Sim、TensorRT、JAX 或上游 CUDA 算子能直接运行。先做算子、精度、小 batch、保存/恢复与速度验证；NVIDIA 仿真/部署部分可能需要独立兼容节点。基础数据工程仍保持 Python/Parquet 的平台可移植性。

建议顺序：固定工位传统伺服/ACT → 需要语言、多任务时比较 SmolVLA → 用目标 G1 数据比较 UnifoLM-WLA/GR00T；π 系列作为强连续 VLA 候选。行走单独评估已有控制器与 RL；需要连续行走操作时再选择全身路线。选型表是实验室建议，不是未经试验的性能排名。

2. 三条组合路线

路线 A：分阶段执行，先获得可解释基线

导航到工位 → 确认稳定站立 → 允许上肢策略执行 → 工具完成与质量复核 → 恢复移动。一次只有一套有明确关节权限的控制链。先测固定工位取放/对位，再扩展工具。这是实验室首轮建议，不能覆盖边走边装配。

路线 B：分层策略＋全身控制器

任务层选择工位/技能；导航给移动目标；操作策略给双手 TCP/关节/运动参考；全身控制器统一跟踪，保持接触和平衡。全身控制器可用优化、RL 或混合方法，不是只能用 VLA。

优化式 WBC 的思想可以写为：最小化手部与基座跟踪误差、姿态和动作变化，满足机器人动力学、足部接触、摩擦、关节限位等约束。示意动力学 M(q)qdd + h(q,qd) = S^T*tau + J_contact^T*f_contact。真实约束和权重要根据设备设计；本仓库没有实现该求解器。

RL 跟踪式控制器可把全身参考与实测状态输入 actor，输出一致的关节命令。上层学习模型的标签必须和它的参考接口相匹配，不能把关节角、TCP 或 latent 互换。

公开候选：NVIDIA GR00T-WholeBodyControl 包含 decoupled WBC 和 SONIC 线路，公开了 G1 的采集、VLA 训练与执行文档。SONIC 把运动表示与控制器配套，GR00T 的 UNITREE_G1 与 UNITREE_G1_SONIC 接口不同。本次只核查文档，不运行该控制栈。GR00T 入口。

路线 C：联合的全身学习系统

策略根据视觉/语言与全身状态同时产生身体和手部参考，底层仍有执行与平衡机制。联合训练数据需要身体、接触和双手同步，单独桌面上肢数据不够。训练更复杂，失败归因也更难。

9. 已做的检查不等于审批

check_industrial_contract.py 核验资料字段与附件 hash。即使文件齐全，也只能报告 document_checks_passed，始终输出 human_review_required=true、robot_deployment_authorized=false。它无法自动判断校准是否真实、授权是否覆盖生产、硬件是否安全或工艺能力是否合格。

4. 一个具体例子：宇树 WLA 并不只读“关节向量”

核查的 unifolm-wla 规范提供统一的 54维动作、60维状态 与有效性 mask；状态与mask拼接后投影器输入120维。末端/基座位姿使用相对当前状态的 SE(3) 表示，其余通道保留来源控制语义。规范示例的动作块是30个动作点。这些是该版本模型表示，不是 G1 拥有54个电机。

更关键的限制：核查版本的 WBC msgpack action server 默认 adapter 只覆盖 Dex1 槽位；Dex5/WBT 客户端与协议需扩展。能训练某种手型不代表现有服务已可执行该手型。来源：动作/状态规范、训练与服务规范。完整revision/hash见代码快照。

我们的 NPZ 是本来源原生维度＋mean/std；直接送给这个54/60维模型会错。需按上游 slot、SE(3)、统计与mask重新派生视图，不能简单补零猜缺失维度。官方 LeRobot 导出只解决存储，不自动做该模型 adapter。
